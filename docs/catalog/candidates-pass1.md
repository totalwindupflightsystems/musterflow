# Catalog growth pass 1 — ranked candidates

Status: pass 1 (proposal + live evidence). Seeded catalog at time of writing: `github`,
`stripe`, `slack`, `discord`, `openai`, `notion`, `linear`, `jira`, `twilio`, `cloudflare`
(`catalog/seed.json`, 10 entries). Nothing below duplicates those ids or re-lists the same
vendor under a second name (SendGrid was dropped for that reason: it is Twilio).

## Method

1. **Spec URLs are probed, not trusted.** Every URL in this document was fetched with
   `curl -sSL -A musterflow-catalog-probe/1.0 -o <body> -w '%{http_code} %{size_download}'`
   and then parsed as JSON (fallback YAML) and checked for `openapi`/`swagger` + `paths`.
   Raw probe lines: `.coding-hermes/evidence/CATALOG-001/specs.txt` (57 probes, 26 HTTP 200).
2. **Every candidate is put through this binary**, not just read:
   `musterflow --data-dir <scratch> connect <SPEC_URL> --name <slug>`.
   Raw transcripts: `connect-sweep.log` — 22 candidates tried, **14 connected, 8 rejected**.
3. **Spec quality is measured**, not eyeballed: operationId coverage, autogenerated ids,
   2xx-with-schema coverage, declared servers, declared security schemes
   (`specs-census.txt`, produced by resolving local `$ref`s).
4. **Rank** = day-one pull for a developer who just installed `musterflow`, discounted by
   whether the spec can actually be driven today. A spec whose `connect` is rejected (or
   whose verbs cannot be generated) cannot be a *default*, so those sit in their own
   "blocked" table instead of occupying ranks they cannot hold.

All work was done on a fresh binary built from HEAD (`sha256 51bfe086…be0fbe6b`), a scratch
data dir per candidate (`/tmp/mf-cat001-verify/<slug>`), and dashboard port **19877** —
the canonical `~/.musterflow` and port 9876 were never touched.

## Why this order

Vercel and Hugging Face are ranked first because they are the two APIs a developer touches on
the same afternoon they install a CLI generator — one to ship a web app, one to move models —
and both survive contact with this binary: real operationIds (Vercel) or stable path-derived
verbs (Hugging Face), real base URLs, and hundreds of operations parsed without hand-tuning.
Ollama and NWS follow because they are the only two candidates that can be *demonstrated with
zero credentials*: a local daemon and a public government feed respectively, which is the
strongest possible proof of the "connect a spec, get a working CLI" thesis and the cheapest
possible first-run experience for a new user. Hetzner takes rank 5 as the representative infra
provider: it parses cleanly, declares a real host, and its 190 operations are the
server/volume/firewall verbs self-hosters ask for first. Everything below rank 5 is ranked by
day-one pull among *drivable* specs, with practicality as the tie-breaker: Kubernetes is
undoubtedly the most important API in the table, but its spec declares no server URL, so the
generator builds zero verbs (`base URL is required`) — a default nobody can run is not a
default. Plaid and Resend follow as the two most-requested "move money / send mail"
integrations, then Sentry for the first-error moment, then the data layer (Atlas, Qdrant,
Typesense), which is real but arrives after the app exists. Public-read APIs are deliberately
bumped up rather than down: six of the twelve drivable specs need a bearer/apiKey token against
their declared public host (Vercel, Hetzner, Plaid, Resend, Sentry, Atlas), Kubernetes needs a
token *and* a cluster, and only three of the twelve — Hugging Face, Ollama, NWS — can be
demonstrated with no credentials at all, which is exactly what makes them the right first-run
experience.

## Notable product findings from this pass

1. **Strict spec validation is the biggest blocker to catalog growth: 8 of 22 widely used
   public specs are rejected on connect.** Five of those rejections are cosmetic spec defects
   that other tooling tolerates (an array example on a string schema, `required: true`, a
   malformed example, a dangling `$ref`, an external `$ref`). A tolerance mode (or
   `SkipValidation` with warnings) would unlock Docker, GitLab, Spotify, Square, DigitalOcean,
   PagerDuty and Weaviate at once.
2. **A spec with no server URL yields zero verbs, silently at connect time.**
   `connect` prints `✓ Connected … Endpoints: 1175` and then every invocation fails with
   `invalid config: base URL is required`. Failing the *connect* (or defaulting the base URL to
   a prompted `--base-url`) would be honest; today the success message is misleading.
3. **Relative server URLs resolve against the spec host.** Immich's `servers[0].url = /api`
   becomes `https://raw.githubusercontent.com/api`. For specs pulled from GitHub mirrors this
   is always wrong; a relative server should be resolved against a user-supplied base or
   flagged for confirmation.
4. **Templated server URLs are stored literally** (`https://{region}.sentry.io/api/0`,
   `{protocol}://{hostname}:{port}`) with no warning, so the first call fails on DNS. Three of
   the twelve drivable specs are in this state.
5. **operationId dialects leak straight into the CLI surface.** kebab-case (Vercel) and
   snake_case-with-tags (Qdrant, Typesense) read well; camelCase without tags (Plaid) flattens
   into 351 ungrouped verbs; slash-style ids (Resend) produce verbs like `emails/cancel`;
   camelCase ids split into `a-p-i` groups; snake_case ids with repeated prefixes (Hetzner)
   produce duplicate group names and `data -centers`. A normalisation pass (group from tag,
   verb from the last id segment) would fix most of this in one place.
6. **Auth coverage gap:** MongoDB Atlas authenticates with HTTP Digest, which no musterflow
   auth type expresses; the spec is otherwise excellent. Either add digest or gate those calls
   behind an operator-supplied header.
