## Harness deltas corrected this window (evidence-backed, not app changes)

1. **Catalog search expectation.** The earlier recipe asserted `GET /api/catalog/search` = 200 while
   supplying a query. `internal/dashboard/server.go:264-297` deliberately returns **404** for a
   query when the catalog backend is absent (DF-035: client-visible not-found, matching the local
   CLI path). The empty-query path returns 200 with `{"results":[],"total":0}`. Both are now
   asserted separately (checks 6–7).
2. **`flow run` stderr assertion.** The old "stderr EMPTY" check conflated the BUG-001 regression
   (raw DuckDB lock warning) with the intentional `--data-dir` routing advisory printed by
   `cmd/musterflow/main.go:121`. The check now fails only on `Conflicting lock` /
   `could not load registry` (check 18). Stdout purity — the contract that matters for piping — is
   separately asserted for both `flow run` (byte-exact) and the generated leaf (`jq` purity).
